# ゲームランドを段階的に整理する

目的は、遊び方・記録・操作を保ち、ゲーム追加や修正で既存ページを壊さないことです。全面的な仕様変更やフレームワーク導入は目的に含みません。

## 進める順番と完了条件

1. **一覧とPR検査の基盤**: `data/games.json` を正本にしてトップ・README・説明書の目次を生成。生成漏れ、構文エラー、リンク切れ、登録漏れをPRで検出する。
2. **変更前の回帰テスト**: 全11作品を390px/1280pxで起動し、代表操作を確認する。得点・終了・再開・保存のある作品は該当する代表経路を検査。既存の3Dゲームセンター詳細テストも維持する。
3. **全ゲームの最初の整理**: HTML（画面）、CSS（見た目）、JS（ゲーム処理）を同じゲームフォルダ内のファイルに分離。スクリプトの順序とclassic scriptのスコープを維持する。整形以外でJavaScriptの構文木が変わっていないことを確認し、同じ回帰テストを実行する。表示・保存キー・ゲームバランスは変えない。
4. **ゲーム内部の整理**: 小さい作品から順に、機能の境界に沿って入力・状態更新・描画・保存を分離する。各作品の得点・ダメージ・勝敗・保存についてテストを追加してから、その作品だけを変更する。

段階1・2と段階3は別PRにする。各PRは前段階を通ったコードを土台とし、テスト結果と残る確認範囲を記載する。段階4は不具合修正・機能追加の必要に合わせて、作品ごとに小さく進める。

## 実装・検証の記録

- 段階1・2: PR #33。全11作品＋トップ・説明書を390px/1280pxで検査し、GitHub Actionsも成功。
- 段階3: 全11作品をHTML/CSS/JSへ分離。整形前後のJavaScript構文木、読み込み順、DOMの内容、CSSルールを比較（空白・色の大文字小文字など表示に影響しない表記差を正規化）。同じ操作テストと既存37種の詳細検査が成功。
- 段階4の最初: 丸をタップ・へびの時間/得点/移動/衝突/レベルのルールをDOMから分離。詳細テストと既存の保存キー互換を追加。終了後に同じフレームで進行を続けないこと、レベル演出がゲームオーバー表示を消さないことも保護。
- 残りの内部整理は下表の順番で進める。ランキング追加はこの計画を置き換えず、各作品の整理と合わせて接続する。
- 共通ランキング: ゲーム別の最高記録、オンラインの部屋別勝利数・通算勝利数、プロフィールの引継ぎを追加。Cloudflare SQLiteを実際に再起動する検査、重複試合の再送、別ブラウザへの引継ぎを検査する。

ランキングはPR #36で追加しました。サーバー/Pages公開成功、記録APIの応答を確認。プロフィール登録→ゲームの記録→通信失敗/再送→別ブラウザへの引継ぎを検査しています。オンラインの部屋内勝ち数は名前単位、全体ランキングは引継ぎコード単位です。

## 3Dゲームセンターの専用入口

- トップとREADME・説明書から軽い `lobby.html` へ。全37種類をクレーン6・立体スポーツ6・スポーツ/お宝5・ビデオ20に分け、検索して選ぶ。選択後に3Dを読み込み、指定の台の前へ移動する。
- 入口の名前・操作説明はゲーム本体のリテラル定義から静的生成する。`data/games.json` の `entry` で入口を指定し、生成漏れ・入口のリンク切れ・ゲーム定義とのずれをCIで検出する。
- 店内探索・従来のURL・景品や自己ベストの保存キーは維持。未知のゲームIDでは通常入口に留まり、選び直せる案内を出す。勝手にゲームを開始したり、プレイ時間を減らしたりしない。

## 名前を登録する前の記録

- 引継ぎコード未発行の未登録プロフィールも正常なローカル状態として読み込む。登録前の最高記録・未送信記録をページ移動/再読込で失わず、名前を登録してから送信する。登録済みの不正なコードは従来どおり破棄する。
- 別ページ相当の独立した実行環境、最高値の維持、登録まで通信しないこと、プロフィール変更時の未送信記録の分離、保存不可を検査。ブラウザでは惑星クリア→再読込→ランキングへ移動→名前登録→送信→失敗/再送→別ブラウザへの引継ぎまで確認する。

## 時間と費用を抑える方法

- 一覧の同期、整形、構文・リンク検査はスクリプトで行う。AIに繰り返し手作業させない。
- CIは軽い静的検査→既存のゲームテスト→ブラウザ検査の順。失敗した段階で止め、同じPRの古い実行はキャンセルする。
- 通常の機械的変更は低コストのモデルで十分。複雑な状態・対戦処理、原因不明の失敗だけ、推論の強いモデルを使う。モデル名や価格の固定値は変わるためここには決め打ちしない。
- 親セッション自身のモデルはエージェントから変更できない。呼び出す子エージェントにはモデルと推論強度を指定できる。このセッションではモデルセレクターの運用は不要という利用者の指示に従う。検証済みの状態はGitとこの計画に残す。
- 対象作品だけを読む・修正する。広範囲の再設計や何度も同じ検査を回すことを避ける。

## 検査で保証する範囲

ブラウザ検査は代表的な起動・操作経路を守るための土台で、全ステージや実機の操作感を保証するものではない。オンラインはWebSocketを再現したクライアント検査であり、実サーバーの疎通確認とは区別する。内部構造の変更時には対象ロジックの詳細検査を追加する。

## 共通設定とゲーム別ランキングの導線

- トップ上部は名前・記録の引継ぎ設定。ゲームごとの「あそぶ」の横に説明書と専用ランキングを置き、ゲーム画面にも同じ案内を生成する。接続テスト用デモはランキング対象外。
- ランキングは指定ゲームだけの順位表を表示し、名前設定から元の順位表へ戻れる。名前登録前の保存・通信失敗後の再送・別端末への引継ぎは維持する。

## へびのレベルアップ表示

- 動き続ける盤面を覆っていた900ミリ秒の表示を、盤面外の専用通知に変更。通知の高さを確保し、出現・消去で盤面を動かさない。得点・難易度・速度・障害物の規則は維持する。
- 390px/1280pxで実際の50点到達・動きの継続・通知の消去・通知中のゲーム終了と再開を検査する。

## 新しい順の一覧とゲーム別の説明書

- 一覧・README・説明書の入口は追加が新しい順→古い順。更新だけでは並べ替えず、新作はゲーム情報の配列先頭へ追加する。
- 説明本文は `wiki/<manual>.html` にゲームごとに分離。基地防衛の操作・武器・敵・コツは基地防衛の説明書へまとめる。共通の記録・引継ぎの説明は入口に残す。
- トップ、ゲーム画面、3D専用入口から個別説明書へ直接進む。以前の説明書の位置指定リンクも該当ページへ案内する。
